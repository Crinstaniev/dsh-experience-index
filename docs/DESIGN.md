# 设计说明

这份文档记录插件为什么长成这样。行为说明见 [README](../README.md)，这里只写取舍。

## 问题定义

DSH 启动时会加载三层上下文：系统提示、`AGENTS.md` / `CLAUDE.md` 指令链、skill 目录。其它 agent（Codex、Comate、Claude Code、Cursor 等）留下的经验文件不在这三层里，于是新会话既不知道它们存在，也不知道其中哪些值得读。

缺口有三个，缺一不可：

1. **发现**：没有任何线索表明某个目录里埋着 runbook。
2. **判别**：目录里的量级不允许全量注入。实测一个仓库里 70%–90% 的文件是会话语料、临时产物和状态快照，真正可复用的只有十来篇。没有分类，读与不读都是错的。
3. **触发**：即使索引存在，模型也可能从零开始设计，最后绕回已有流程。

## 非目标

- **不是检索器**。不提供 `search` / `show` 工具，不做全文索引、heading 切分、向量化。正文由模型用 `read` / `grep` / `glob` 自己取。理由：自建检索器是在用更差的实现替代宿主已有的工具，而且会让索引与正文产生两份真相。
- **不复制正文**。数据库只存路径、类别、标题、大小、mtime。文件被改动时，最坏的结果是标题过时，而不是索引里的旧正文覆盖磁盘上的新内容。
- **不自动发现目录**。不扫描磁盘找仓库。当前目录来自工作区注册表，其余由用户显式输入。扫描磁盘会让"打开了多少目录"变成"索引列表有多长"。

## 目录作用域（Scope）

索引单位是一个**显式目录**，而不是仓库根。理由：

- 单仓库多子项目时，经验属于子项目。对 `services/api/` 工作的人不需要看到 `services/worker/` 的 42 条会话日志。
- 非 git 目录（专项资料、临时实验）同样可能有经验文件。
- 同一仓库允许父子目录各自索引，两种视角都成立。

**嵌套时最深优先**。会话只注入包含 cwd 的、路径最长的那个 scope。不合并、不追加父级指针——父级内容往往会稀释当前任务真正需要的信号。

**路径相对 cwd 渲染**，不是相对 scope。scope 是子目录时，相对 scope 的路径在模型站着的位置无法解析。

## 级联是渲染规则，不是工具层级

"级联"体现在注入文本的折叠策略上：

| 条目数 | 渲染 |
|---|---|
| ≤ `smallCategoryLimit` | 逐条列出路径 + 一句话说明 |
| > 上限 | 折叠成「目录 + 数量 + 最新日期」 |

折叠后模型仍能自己 `glob` 那个目录，所以折叠不会丢失可达性，只丢失一次注入的成本。

## 噪声要显式命名

日志类、状态类文件默认不展开，但**必须**留一行负向路标：

```
Not reference material: .codex/tmux-remote-logs/ (74 session logs)
```

不写这一行的后果比省略更糟：模型会 `grep -r` 整个 `.codex/`，把 tmux 日志当成证据。

## 过期检测：廉价指纹

手动索引意味着"库里的快照"与"磁盘现实"必然分叉。检测方式必须便宜，否则每次会话首步都在扫盘：

- 对已索引文件逐个 `stat`，比对 `(size, mtime)`
- 对**可能产生候选的目录**比对 mtime（只记录这些目录，不记录所有走过的目录——含大 `.codex/tmp` 的仓库会产生上千个无意义 stat）
- 忽略规则文件的摘要
- 索引器版本

检测到差异只**标注**，不自动重建。自动重建会让"索引何时变化"变得不可预测，也会在会话首步引入写操作。

## fork worktree 的复制语义

worktree 独立索引，但首次进入时从主仓库的对应 scope 复制：

- 映射用「相对仓库根的路径」：`main/sub` → `worktree/sub`，不是一个仓库一个 scope 的整体复制
- **只复制元数据，不复制指纹**。fork 出来的文件 mtime 必然不同，抄指纹会导致新 scope 一打开就判过期
- 复制后逐条 `stat` 校验，丢弃本分支不存在的条目并计数（这是预期差异，不是错误）
- 不发现分支里**新增**的文件——那需要一次完整索引，属于手动行为

## 手动 vs 自动的边界

| 动作 | 谁决定 |
|---|---|
| 建索引 / 重建 | 人（UI 或 HTTP） |
| 读哪篇文档 | 模型（`read` / `grep`） |
| 标注过期 | 插件（廉价检测） |
| 重建过期索引 | 人 |
| 排除某个 scope | 人 |

模型面没有写权限。索引是"有副作用、可治理"的动作，如果允许模型随时重建，数据库会变成它随手写入的黑盒。

## 唯一的主动干预：未索引提示

目录里有 `.codex` / `.comate` / `.claude` / `.agents`，但没有任何 scope 时，注入一行提示，并且：

- 每目录 `hintRepeatDays` 天内最多一次
- 首次索引完成后永久静默
- 提示里报出**具体目录名**，让人一眼看出这行为什么出现

泛化提示（"建议建立索引"）会被习惯性忽略；指名道姓的提示不会。

## 度量

判断插件是否有效，只看两个数：

- `scope 路标注入次数 / 会话数`
- 索引里的路径被模型 `read` / `grep` 直接命中的比例

第二个数接近 0 说明"索引"这个形态不成立，应该改成首步直接展开 top-3 全文。插件目前没有内建埋点，需要从会话日志里统计。
